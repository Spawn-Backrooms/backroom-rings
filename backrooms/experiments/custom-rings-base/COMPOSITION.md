## Selected base candidate (subject to feasibility)

Use a dedicated nonfinancial application ring rather than general-purpose hook extensibility. This is a small, separate program/profile/version, not a feature flag that lets a normal transfer skip the verifier. Reuse upstream ring and SPP machinery. First qualify whether a unique zero-value data note, one input/one live output plus upstream-required padding, and application proof over the same anonymous settlement are supported at the pinned revision. If not, identify the minimum versioned upstream change and qualify it. Do not replace this experiment with a financial transfer or a plaintext application journal.

Provision the room in a separate, explicitly visible genesis operation. The upstream hidden-owner rail needs a live input; do not claim anonymous genesis or enrollment. The genesis verifier must establish the canonical unique room checkpoint and authorized writer membership; it may not be an unrestricted deposit path. In the later hidden-owner operation:

1. Preserve the upstream account, ring proof, and SPP checks. In the dedicated ring transfer processor, add mandatory application proof verification **before** the sole ring-PDA-signed SPP CPI. Derive the statement from the exact validated frame, current bound accounts, and pinned application/verifier identity. Reject unapproved keys and programs.
2. Bind the application circuit to that same ordered settlement/private transaction hash and first nullifier, room commitment, input checkpoint and successor, policy and tracking state, native grant and original acceptance. The circuit must open the same notes and establish the same admitted private actor as the actual input owner, without publishing a stable identity or exposing witness fields. The existing public writer-signature check must not be carried over as the anonymous authorization path. Use the pinned SDK/prover conventions, independently review the actual relation, and generate version-specific artifacts. The reference fixture does not choose the final proof encoding.
3. Restrict the dedicated ring's dispatch and configuration so no ordinary confidential transfer, public-owner rail, authority/delegate move, merge or unrestricted deposit can consume or replace a room note. Do not enable permanent delegate. Native authorizations remain canonical; require exact current grant and predecessor. Preserve one original on retry. Disallow public asset legs or exits for the learning advance. Test that the full transaction rolls back on any failure.
4. Keep genesis and advance state bound to separate reviewed application artifacts. Confirm no second live checkpoint can be created by an alternative path. Pin ring/application/program/key identities and require fresh setup before production. Treat enrollment, fee payer, counts, timing, known-owner links and designated auditor/prover visibility according to the upstream [privacy document](https://github.com/helius-labs/custom-privacy-rings/blob/02bca33729051798834ecbb4d94e968cdc0ef9b8/docs/design/privacy.md). A local fixture cannot prove external unlinkability.

## Executable acceptance oracle

`node --test backrooms/experiments/custom-rings-base/reference-gate.test.mjs`

37 cases passed locally on Node 22.16.0. `reference-gate.mjs` models matching independently established **synthetic facts** for a single accepted advance; it is intentionally not a signature/proof verifier, parser, wire schema, or native authorization service. The fixture actor is an abstract equality label, never a proposed public owner tag. The current root values model a strict selected snapshot, not a claim that upstream already enforces this exact root policy. The test of linked public owner covers a fixture relation only, not general traffic anonymity. The oracle does not test genesis, actual program dispatch, proof verification, Solana atomicity, or recovery. Do not export it from the application SDK or use it in a production authority decision.

The next implementation must turn the negative cases into actual coherent witness mutations and transaction attempts, independently derived from real program/proof/validator outputs. Include absent application proof, bad genesis, direct ordinary transfer and merge/authority bypass attempts, exact frame rebind, current grant revocation, no state advance on refusal and restart recovery. Record actual accepted chain state. CR01 remains open for fork and validator baseline. CR02 and CR04 remain open until actual implementation and independent review.
